# 可复制的跨题目提示词

性质：从本包协作观察提炼的**待各队伍验证模板**，不是已经跨模型/跨题目量化证明稳定性的提示词产品。第一次使用按P3记录实际效果；保留失败，不只选成功回答。

## P1：算法描述 → 软硬件划分

复制以下整段，替换花括号内容后交给模型：

```text
你是本题的软硬件协作分析助手，只读我提供的材料，不运行硬件。
项目绝对路径：{项目根}；算法入口与规格：{文件/函数/页码}；版本：{提交/哈希}。
输入输出：{shape、dtype、layout、单位、最大/常见规模、频率}。
目标：{吞吐、尾延迟、功耗/资源预算、允许误差}；未知项必须标未知。
现有平台：{器件、时钟、内存/带宽、AXI接口、工具/驱动版本}。
权限：仅分析；不得写原工程、综合、联网、下载权重或上板。
第一轮只输出：
1. 算子/阶段表：输入、输出、数据量、依赖、可并行性、状态与边界条件；逐项引用文件位置。
2. PS/PL划分候选：估计的来源、搬运与同步成本、调度/缓冲所有权；区分测量和假设。
3. 最小验证矩阵：独立黄金参考、边界/错误输入、位宽/舍入/饱和、C→RTL→平台的独立门禁。
4. 不可下结论的缺口；不得凭目标时钟生成实测FPS或加速比。
人工确认后，第二轮仅为一个候选提出一个可回滚实验，列出改动文件、测量范围和失败停止条件。
```

验收：每条划分有输入依据；没有实测的数据必须标假设；端到端开销不能被核周期替代。来源：HLS前后处理专题中“核结果≠平台性能”的源码与覆盖范围观察。

## P2：综合/实现报告 → 瓶颈假设与最小实验

```text
只分析以下原始报告，不调用EDA工具：
项目绝对路径={项目根}；报告绝对路径/SHA={报告及哈希}；源码版本={版本}。
阶段={HLS/综合/实现}；器件/时钟/约束={已知值或未知}；目标={指标及预算}。
请先提取带原文位置的表：stage、latency/II（适用时）、WNS/WHS、未约束路径、DRC、LUT/FF/BRAM/DSP。
没有字段不得填0；HLS目标时钟不是实现后时序。资源缺项不得按未使用处理。
只在证据足够时给出最多3个瓶颈假设：报告证据→可能原因→单变量修改→反证实验。
区分算子依赖、访存、接口/搬运、资源复用、布局布线，不能凭负WNS猜具体RTL根因。
输出：转录表、需要人工核对的位置、一个最小实验、预期可观察变化、回滚方法、失效条件。
不得改约束掩盖时序，不得移除错误处理/黄金比对，不得承诺未实测收益。
```

验收：转录值由人工比对原文，然后可交给validate_evidence.py的qor模式；它只检查转录合同及来源哈希，不验证模型转录是否正确。

## P3：失败复现 → 回归与效果记录

```text
待复用任务={具体任务}；项目绝对路径={根目录}；模型/版本/日期={记录}。
可修改副本={路径}；禁止动作={网络/构建/硬件等}。
观察到的失败={实际日志与退出码，不是推测}；预期={规格引用}；输入={路径和SHA}。
先判断环境、接口、数值、状态机或证据链哪个阶段最先失败，给出依据，不重写整个工程。
先构造最小负例并证明旧行为失败，再做最小修复，运行正例、负例和受影响回归。
若无法安全执行，输出待执行命令与阻塞，不能写成已执行。
最终表：输入版本、失败触发、修复范围、实际命令/退出码、通过/失败/跳过、未覆盖、可迁移条件。
对本提示词自身记录：是否需要人工纠错、纠错原因、是否遗漏关键约束；不从一次成功推稳定性。
```

验收：至少一个真实负例；跳过单列；命令完成与业务完成分开。可配合[实验记录](/home/amd/kv260-ofdm-reproduction/skill/templates/RUN_RECORD.md)和[缺口模板](/home/amd/kv260-ofdm-reproduction/skill/templates/GAP_RECORD.md)。

## 通用失效条件

不提供源码/报告、版本不匹配、黄金参考不是独立来源、硬件权限/接口未知时，只能得到缺口清单。上下文超长导致模型遗漏引用时分阶段重放；模型输出必须由人或校验器复核，不能直接变成设备指令。
