# 缺口 / 风险 / 阻塞记录模板

此文件是记录格式，不是已确认问题清单；当前真实缺口查看[已有报告](/home/amd/kv260-ofdm-reproduction/report/KNOWN_GAPS.md)。

适用：缺文件/环境/实现/验证/权限；用法：每个阻塞复制一份，绑定输入版本与真实观察，满足关闭条件后才关闭。失效：只有推测而无观察时标“待分析”，不能当已证实故障。经验来源就是上述实际缺口报告；已验证效果为模板能表达该报告的缺失依赖及未验证项，不等于已经补齐实现或经过陌生队伍现场评估。

- 编号、发现时间、关联技能：
- 问题类别：缺文件 / 版本冲突 / 环境 / 实现缺失 / 验证缺失 / 安全边界。
- 影响的目标与不能作出的结论：
- 实际源码/配置/日志绝对路径、行号与版本：
- 预期行为与观察到的行为：
- 最小复现输入/命令及退出码：
- 是否仅有历史描述而没有当前证据：
- 可用的临时绕行方案及其限制（无则写无）：
- 禁止的绕过方式（如删校验、改哈希、放宽联锁）：
- 修复所需文件、依赖、设备或授权：
- 拟修改的副本和不允许改动的原工程：
- 关闭条件与对应测试：
- 当前状态：待分析 / 阻塞 / 待验证 / 已验证关闭。

“生成了文档”“存在脚本”“某次旧日志通过”不能单独关闭实现或实机验收缺口。
