# 技能公共执行约定

适用于本次新增技能，不自动覆盖原工程行为。具体实现以技能列出的源码为准。项目根目录为`/home/amd/kv260-ofdm-reproduction`，原工程只读；技能不等于宿主IDE已经安装、启用或授予工具权限。

## 1. 操作分级

| 等级 | 示例 | 前提 |
|---|---|---|
| R0 只读分析 | 阅读源码/日志、计算哈希、检查文档引用 | 不导入可能有副作用的项目模块 |
| R1 离线执行/文档 | 已审查单元测试、模拟UART/TCP、文档修改 | 明确修改范围，使用独立输出目录 |
| R2 本机构建 | HLS、XSCT、Vivado、容器构建 | 明确构建授权、工具/许可证、输出与资源范围 |
| R3 联网/设备访问 | 模型API、SSH、部署、真实串口probe、相机 | 确认端点、数据外发、设备身份与访问范围 |
| R4 改变硬件状态 | overlay、JTAG、驱动启动、标定、扭矩/运动 | 操作者明确批准、独占资源、现场条件和停机方案 |

级别是本包的审查分类，不是工具权限机制。某命令看似只读但会导入驱动/启动服务时按实际副作用升级；`--help`只有确认在副作用之前解析时才可安全调用。默认不能从R1自动升级到R2或R4。

## 2. 来源与证据

优先使用匹配版本的实际代码、参数解析、工件元数据、当前日志，再用README解释设计意图。源码和说明冲突时记录冲突，不挑有利的一项宣称完成。

| 标签 | 可支持的结论 | 不可支持的结论 |
|---|---|---|
| 静态检查 | 文件存在、代码路径、参数/默认值、哈希匹配 | 程序已跑通、板卡安全 |
| 离线执行 | 特定输入与环境下的单测/C/RTL结果 | 实际RF/相机/机器人验证 |
| 构建结果 | 当前源码的指定工具阶段产物 | 已烧录、系统功能通过 |
| 历史记录/imported | 原实验在其记录条件下的报告 | 本次重新验证、当前板卡匹配 |
| 本次实机 | 当前设备/配置/时间窗内实际观测 | 未测场景、永久安全、数据集精度 |

通过至少需要完整退出状态、预期标志或测试框架结果、无相关错误及对应输入。看见日志中的PASS子串不够；摘要的hardware_actions字段只是记录声明，必须同时审核实际命令/源码。任务仍在运行时不能标完成。

## 3. 工作目录与写入

1. 修改前检查封存，记录预期差异。不要在原工程或历史测试结果目录写入。
2. 构建前确认符号链接真实目标；包内build链接仍可能覆盖归档构建产物。
3. 新实验使用不存在的独立目录；失败目录保留，不重复使用导致旧二进制/日志混入。
4. 重建源码副本是独立工作项；不能只复制一个子目录而遗漏包内跨目录链接。
5. 用来源清单追踪原样文件；新增技能/日志不冒充原始工程材料。
6. 日志全部停止写入且差异审查完成后才seal。全包SHA不包含自身和指定可变报告，以验证器排除列表为准。

## 4. 命令与结果记录

每次运行记录绝对cwd、参数数组、解释器/工具路径与版本、输入SHA、环境变量名及非敏感值、开始/结束时间、退出码、超时、跳过、日志路径和输出SHA。

不要在shell管道中丢失真实退出码；使用tee时启用pipefail或显式读取各阶段状态。出现终端捕获不完整时读取落盘日志/结果并检查进程，不盲目重跑同一个输出目录。并行只用于互不依赖的只读检查；构建、测试和封存不能竞争写同一批文件。
