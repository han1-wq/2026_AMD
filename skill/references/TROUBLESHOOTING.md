# 跨模块故障定位手册

先确认任务层级和最后一个确有证据的成功阶段。失败日志必须保留；禁止先降低安全检查、生成空文件或修改哈希清单。

## 适用、效果与来源

用于有明确症状但尚未定位层级的项目；先记录触发输入/版本，再按下面顺序检查。失效：版本/设备状态未知或缺实际日志时只能形成待验证假设，不直接操作硬件。每条来源见对应专题的“经验来源”：有些是[原回归日志](/home/amd/kv260-ofdm-reproduction/sim/results/packaging-validation/summary.json)中的跳过/覆盖观察，有些是[缓冲源码](/home/amd/kv260-ofdm-reproduction/src/ps/kv260_B3136/runtime/hardware.py)或[真实缺口](/home/amd/kv260-ofdm-reproduction/report/KNOWN_GAPS.md)。已验证效果是检查路径可追溯，不声称表中所有事故均亲历或均已修复。

## 1. 推荐排查顺序

1. **来源和文件**：SHA、软链接、模型/硬件配套、旧绝对路径。
2. **环境和权限**：CPU架构、解释器、依赖、工具版本、许可证；不改变系统环境来试错。
3. **纯逻辑**：参数、状态机、单位、shape/stride/端序、错误返回。
4. **模拟执行**：固定向量、模拟串口/网络、C/RTL边界及超时。
5. **构建集成**：IP/BD、时钟/复位、AXI所有权、约束、时序和资源。
6. **受控设备实验**：仅获准后检查实际设备身份、独占、观察、退出和停机条件。

不要从第1层文件缺失直接跳到第6层上板碰运气。

## 2. 故障速查

| 症状 | 优先检查 | 不应采取的“修复” |
|---|---|---|
| 哈希不一致 | 预期改动列表、来源清单、旧封存 | 直接seal覆盖旧证据 |
| 链接失效 | 跨分类目标是否一起复制 | 链回原工程掩盖缺失 |
| 有README但入口缺失 | 原路径索引、排除清单、模块版本 | 从另一个工程拼同名文件 |
| NumPy/torch缺失 | 解释器绝对路径、架构、锁定依赖 | 往原venv/系统pip强装 |
| GUI跳过 | DISPLAY、Tk和测试设计 | 将skip统计为pass |
| HLS cosim缺产物 | 当前源码综合是否成功、工具环境 | 复用旧RTL报告验新源码 |
| 颜色/坐标不对 | BGR/RGB、letterbox、fix_point、尺度布局 | 盲目放大容差 |
| 后处理候选多时异常 | overflow与整帧CPU回退 | 只截前256个当有效 |
| 视频显示卡/旧帧 | 帧序号、新鲜度、applied config_id、队列 | 用旧截图证明本次有效 |
| CMA/FPGA锁冲突 | 已有推理进程、在途DMA、资源占用 | SIGKILL并重载overlay |
| UART只有ACK | matching RX记录与session/message | 当无线回环通过 |
| TCP回传阻塞 | 同连接上传/排空、单客户端、ACK窗口 | 同板双客户端send/receive |
| 驱动启动发生姿态动作 | 初始化源码与设备身份 | 称“只是启动，不会运动” |
| 导航质量差仍运动 | 实际quality_interlock及覆盖 | 隐藏默认false |
| SO101失联仍供电 | HOLD/HOLD_FAILED与扭矩策略 | 声称已硬件急停 |
| RoArm ACK但零位移 | 编码器前后值、dispatch、motion_verified | 用模型done或SDK返回判完成 |

## 3. 最小失败记录

保存绝对入口/cwd、参数、版本、输入SHA、实际输出/退出码、预期行为、第一次失败的阶段、是否触及硬件及当时资源状态。不要粘贴密钥或未脱敏的个人数据。使用[缺口模板](/home/amd/kv260-ofdm-reproduction/skill/templates/GAP_RECORD.md)。

## 4. 软件测试失败后的边界

- 代码问题：在获准工作副本做最小修复，新增能复现失败的测试，再跑关联回归。
- 环境问题：记录缺依赖和可用解释器；没有安装授权不改环境。
- 硬件相关问题：停止离线推断，列出需要操作员提供的实际状态/日志。
- 终端输出缺失：检查落盘结果及进程完成状态；不并发重启同一输出目录。
