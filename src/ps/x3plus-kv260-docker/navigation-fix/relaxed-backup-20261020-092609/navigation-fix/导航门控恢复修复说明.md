## 原因与证据

1. 前次现场观测的门控状态为 `ready=false / high_pose_uncertainty_initial_pose_required`，输出 `/cmd_vel` 为零。采样时位置标准差约 4 cm、yaw 标准差约 0.27°，小于默认 35 cm、约 17.2° 门槛。这些历史观测说明定位确认已被早先事件撤销，不能证明当时传感器一直健康。
2. 原 `navigation_guard.py` 的 `tick()` 遇到任何质量检查失败都会调用 `invalidate()`，清除 `initial`。此后 `check()` 遇到 `initial is None` 直接返回历史原因，数据恢复也不能重新放行。一次短暂协方差或时间戳异常即可永久锁定，目标被拒绝或取消，车不会执行位置或朝向。
3. 原 `start-navigation.sh` 即使复用同地图健康实例，也主动调用 `/navigation_guard/reset` 撤销定位。这是另一条要求重设位姿的路径；电脑“启动导航 RViz”本身只打开查看器，不调用板端启动脚本，因此不能把这条路径归因于每一次 RViz 点击。
4. 当前 RViz `2D Pose Estimate` 发布 `/initialpose`，`2D Nav Goal` 发布 `/move_base_simple/goal`，目标四元数被完整转发。真实 AMCL + move_base 隔离测试验证目标位置、不同终点朝向和仅旋转目标能执行；没有证据把本次已观察到的完全不动归因为箭头方向被丢弃。

尚不能确认的部分：断线前是否还存在过期扫描、时钟不同步、规划失败、底盘订阅或串口驱动问题。历史日志存在控制/代价地图更新耗时过长，不能据此确定当前硬件根因。

## 新行为

| 事件 | 行为 |
| --- | --- |
| 冷启动、换图、定位跳变、AMCL 序列重启、人工 reset | 归零、撤销目标，需新初始位姿 |
| 短暂协方差超限、scan/AMCL/TF 过期、地图匹配失败 | 立即归零、撤销内部执行；保留公开任务及完整目标位姿 |
| 首次异常起 5 秒内恢复，并连续健康 2 秒 | 旧规划确认终止、速度静默后，从当前位置自动重新规划到原位置及最终朝向；不需重发目标或初始位姿 |
| 5 秒内不能完成稳定恢复，包括反复抖动 | 锁定，需人工核对并重新初始化 |
| 每个目标已自动恢复 2 次后再故障 | 终止该目标，不再自动恢复；不放宽定位门槛 |
| 主动 cancel、stop、重设初始位姿、书签恢复 | 终止旧任务，恢复数据也不会续跑 |
| 暂停期间收到新 RViz / action 目标 | 替换旧任务；新目标等待定位恢复后执行，不排队执行旧目标 |
| 同一地图健康实例复用 | 调用新 `/navigation_guard/stop`，撤销旧目标但保留定位状态 |

`~stable_seconds=2`、`~transient_timeout=5`、`~max_auto_resumes=2`（设为 0 可禁用自动续航）；要求 `0 < stable_seconds < transient_timeout`，5 秒包含恢复验证时间。原有传感器时效、协方差、初始位姿一致性、激光匹配和射线冲突门槛均保留。恢复期间仍比较 map→odom 修正变化，防止“恢复”掩盖定位跳变。初始定位尚未确认时，不进行自动确认绕过。

### 任务、内部执行与速度安全

公开 `/move_base` action 在短暂故障期间保持 ACTIVE，不提前报告 PREEMPTED。保留完整目标 Pose（包括四元数）；定位恢复后只刷新内部目标时间戳，发起新的内部 action ID，让 move_base 从当前定位重新规划。只有当前执行成功，才向公开任务报告 SUCCEEDED。

任务 epoch 与内部执行 epoch 分离。cancel、stop、新目标替换、reset、换图、AMCL 重启和定位跳变使旧任务失效；旧执行迟到的成功、激活和反馈不能覆盖新任务。规划器 ABORTED/REJECTED/LOST 不自动重试。旧规划未在恢复窗口内确认终止，也不恢复。

停车时清空速度缓存，旧 action 结束并连续至少 0.3 秒未收到非零内部速度后，重建内部速度订阅，丢弃旧 TCPROS 接收队列；回调携带执行 epoch，过期回调不能进入新执行。新规划进入 ACTIVE 之前不放行。这里不会重放速度，但 `/navigation_internal/cmd_vel` 仍是无时间戳、无 goal ID 的 ROS1 Twist：不能识别恶意发布者或在新连接上伪造的旧速度，依赖可信的单一 move_base 发布者。此次验收不能代替底盘急停和独立安全控制。

`/navigation/localization_status` 包含 `task_state`、`task_reason`、`goal_retained`、`resume_count`、`max_auto_resumes`，并保留 `current_fault`、`initial_pose_required`、`latched_reason`、`recovery_remaining_s`。界面区分暂停保留目标、自动重新规划、任务终止和需要初始化，不再把暂时停车误报为目标取消。

1. 重开电脑控制台、打开导航 RViz。对照实车和激光地图设置一次 `2D Pose Estimate`，等待 ready。箭头起点是车在地图上的实际位置，方向是车头。
