## 失败案例的准确含义

真值为 `(x=2.0 m, y=1.0 m, yaw=0.6 rad)`。将初始位置保持不变、朝向设为 `0.6 + π` 后，第二次复现记录：

- AMCL 估计约 `(1.9765, 0.9800, -2.5428)`。
- 位置误差约 0.0309 m，但朝向误差约 3.1404 rad，接近 180°。
- 门控状态为 `ready=true`，激光终点匹配率 `0.7667`，高于现有门槛 `0.65`。
- 增强回归断言 `Reversed initial heading accepted` 失败，退出码 1；不能标记为通过。

当前检查的是激光终点邻近地图障碍的比例，并不是对位姿唯一性的证明。场景虽有非对称障碍，但大部分射线仍可能在反向位姿下落到相似边界。AMCL 协方差较小、与人工设定的初始位姿一致，也不等于朝向真实正确。

下一步应单独评估更有区分力的扫描一致性检查（例如障碍遮挡及自由空间矛盾），并在重复/对称地图、多位置、多朝向和真实数据回放中验证。不能只提高一个匹配率阈值、在一个场景中通过后便认为解决。固定物理参照或外部标志也可提供额外约束。

测试源码已增加初始朝向误差、反向输入和导航终点朝向断言。生产门控未改，因此当前增强版回归预期会暴露这个尚未解决的问题；不要为了得到绿色结果而移除断言。

## 建议机制：按地图保存固定起点和朝向

### 操作流程

1. 在现场设置可重复摆车的位置线和车头方向箭头，例如“起点 A”，选择激光可见特征丰富、避免长直对称走廊的位置。
2. 在 SLAM 建图完成、最终地图保存后，让车处于该物理参照位置，核对地图/激光/车头方向，记录机器人 `map → base_footprint` 位姿作为书签；或在已有地图导航中，经人工核验定位后保存可信位姿。
3. 书签保存名称、`map` 坐标系、x/y/yaw、合理初始协方差、地图内容指纹及分辨率/原点等元数据。不能只用地图文件名，也不能把 YAML 的 origin 当作机器人起点。
4. RViz 显示命名起点和朝向箭头。上位机提供“保存当前参考位姿”“查看起点”“恢复初始位姿”，将标记与导航目标区分开。
5. 下次启动时先选相同地图，把车实际摆回对应位置和朝向；用户明确确认后，发布带当前时间戳的 `/initialpose`。
6. 恢复前撤销旧目标/定位确认，恢复后重新等待定位质量检查与人工激光轮廓核验。只恢复位姿，不发送导航目标、速度或自动巡航；门控误放行问题解决前不能仅凭 ready 自动启动。

### 必须保留的限制

- “标记地图位置”“给 AMCL 一个初始估计”“确认真实定位”是三个不同动作，不能混为一谈。
- 正在运行的 gmapping 建图与加载已保存地图的 AMCL 导航不同；`/initialpose` 是当前 AMCL 导航的初始化入口，不是重设 gmapping 起点的通用方法。SLAM 查看器应继续保持观察用途。
- 建图过程可能发生回环校正，不能不经核验就把开始建图时暂存的坐标绑定到最终地图。书签必须和最终地图坐标一致；地图修改或替换后拒绝直接复用，要求重新标定。
- 小车被搬到未知位置或朝向时，不得直接恢复旧起点。无物理参照时，可用现有 `2D Pose Estimate` 人工设位置与方向，再检查激光匹配；若要求自动识别实际位置，需要另行评估标志物、停靠基准或全局重定位。
- 书签可以减少每次手工点选误差，但不能消除轮滑、外参、时间戳、里程计或环境对称引起的定位偏差。
