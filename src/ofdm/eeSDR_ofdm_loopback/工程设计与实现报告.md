## 摘要

本工程实现一套以 Zynq-7000 SoC 和 AD936x 射频收发器为核心的 OFDM 软件无线电系统。FPGA 可编程逻辑（PL）中包含 OFDM 发射、接收和包处理逻辑；处理系统（PS）负责 AD9361 配置、DMA 数据搬运、以太网/TCP 和 UART 服务。主机数据进入板卡后，经 DMA 或历史 AXI-Lite mailbox 提交给 OFDM 发射链路，通过 AD936x 发射；接收端对 RF 输入进行同步、解调和纠错，FCS 正确且长度有效的数据才被提交到接收队列，再由 PS 返回主机。

工程支持两类板级数据面集成：历史/简化的单包 mailbox 回环和面向 SG-DMA 的包队列回环。主机端当前 DMA 客户端提供 UART 数据测试及 TCP 图像分片回环。源码默认参数、旧版部署说明和 DMA 实测文档之间存在版本差异，使用前必须确认硬件导出文件、bitstream、固件和 RS 参数相互匹配。

**关键词：** Zynq；AD9361；SDR；OFDM；IEEE 802.11a 风格 PHY；RS(255,239)；DMA；lwIP；无线回环

## 1. 项目概述

### 1.1 项目目标

从工程结构和数据通路看，项目目标是搭建一个可在 FPGA/SDR 硬件上工作的 OFDM 收发系统，并建立可重复提交、回收和校验用户数据的软件通道。它同时服务于：

- OFDM PHY 的 RTL 开发与仿真验证。
- AD936x LVDS 数字接口和射频收发链路集成。
- 包级无线回环和错误纠正验证。
- 通过 UART/TCP 传送用户数据或图像文件。
- 使用 DMA 与软件队列测试持续数据搬运、背压和链路错误处理。

### 1.2 系统边界

这里的“loopback”主要表示**单板 RF 回环**：发射端的射频输出必须通过天线耦合、射频线缆/衰减器或外部 RF 连接到接收端；RX 返回的是接收机实际解调后的数据，而非主机软件或 PS 对 TX 缓冲区的简单复制。测试连接形式、衰减和射频安全要求应以实际硬件板卡资料为准。

协议文档说明，DMA 版本使用一块板：Host → UART/TCP → PS/DMA → OFDM TX → RF → OFDM RX → DMA/PS → 原 Host 通道。该版本不要求第二块板或应用层 RF echo。[`host/PROTOCOL.md`](host/PROTOCOL.md)

## 2. 系统总体架构

系统端到端数据流、错误分支、DMA 提交条件以及 mailbox 替代路径见：[系统详细流程图](系统详细流程图.md)。

### 2.1 PS 与 PL 分工

| 子系统 | 主要职责 |
|---|---|
| Zynq PS（ARM Cortex-A9） | AD9361 初始化与控制；SG-DMA 描述符和 DDR 缓冲区；缓存一致性处理；lwIP TCP 服务；UART 业务协议；分片、ACK、重试、图像重组和状态上报 |
| Zynq PL | AD936x LVDS 数据接口；OFDM TX/RX PHY；CRC/RS；TX/RX 包缓冲；AXI-Stream 与 AXI-Lite 包接口；状态计数和调试 ILA |
| AD936x | RF 收发、本振和带宽/增益配置、ADC/DAC 与数字 LVDS 样本接口 |
| Host | UART/TCP 控制与数据提交；图像/数据重组；CRC、字节相等性及 SHA-256 验证 |

### 2.2 端到端数据流

```text
主机应用
  ├── UART：A5 5A + 长度 + OF 数据包
  └── TCP：长度前缀 + OF 元数据/分片记录（端口 5001）
           │
           ▼
Zynq PS：services.c / link.c
  协议校验、限流、ACK/重试、分片处理
           │
           ▼
SG-DMA（DMA 模式） ── DDR 缓冲区/描述符
           │ AXI-Stream，包前有 16 字节本地 TX 元数据
           ▼
PL TX 包适配器 → CRC/RS → 802.11 风格 OFDM TX → I/Q 缩放
           ▼
AD936x LVDS TX → RF 发射 → 外部 RF/天线耦合路径
           ▼
AD936x LVDS RX → I/Q 缩放 → OFDM 同步/解调/译码 → RS/FCS
           │ 只提交完整、长度正确且校验通过的数据包
           ▼
PL RX 包队列 → AXI-Stream → SG-DMA → DDR
           ▼
Zynq PS：link/service 返回数据与结果
           ▼
主机收到 RX 数据，校验 CRC 和逐字节一致性
```

上述 SG-DMA 路径是当前 DMA 软件/协议文档描述的模式。板级 RTL `ad936x_ofdm_TOP` 的 `DMA_ENABLE` 参数默认值是 `0`，默认生成 mailbox 分支；DMA 构建需要在 Vivado/IP 集成时将该参数配置为启用。因此工程源码默认实例和 DMA 部署不能视为同一个配置。[`rtl/board/ad936x_ofdm_TOP.v`](rtl/board/ad936x_ofdm_TOP.v) [`firmware/build_dma_sw.tcl`](firmware/build_dma_sw.tcl)

### 2.3 时钟与复位

- 板级顶层从 AD936x LVDS 接收数据时钟建立 PHY 数据时钟域。
- `clk_wiz_0` 从该时钟生成 OFDM/AXI-Stream 所用 `data_clk`；工程接口元数据记录为 80 MHz。
- 固件参数设置复数采样率 40 MS/s，注释说明 1T1R 下数字数据时钟为 80 MHz。
- PS/AXI 域的 `TR_mode` 通过两级同步寄存器进入 AD936x 数据时钟域。
- AXI 时钟转换由 Block Design 完成；不同域之间还使用复位同步器、AXI FIFO 或显式 toggle/bundled-data mailbox 握手。
- `board/TOP.xdc` 中有 50 MHz 板级时钟和 AD936x 数据时钟约束；当前可见约束对若干外部接口的输入/输出延时描述有限，实际板级时序仍需完整审查。

## 3. 硬件平台和板级接口

### 3.1 目标硬件

`board/ZYNQ_bd.bd` 记录目标器件为 `xc7z020clg400-2`，Vivado 2022.1。Block Design 的树包含 `processing_system7_0`、复位、AXI 外设和 `ad936x_ofdm_TOP_0`。顶层 `rtl/board/TOP.v` 引出 PS DDR/FIXED_IO、AD936x SPI、LVDS RX/TX、控制 GPIO 和状态 LED。

### 3.2 AD936x 数字接口

`ad936x_phy_TOP` 由 RX 与 TX 两部分组成：

- RX：差分数据时钟、6 对数据线和 frame 输入，解串为两个通道的 12-bit I/Q 与有效信号。
- TX：接收两路 12-bit I/Q，编码成 6 对差分数据线、frame 和反馈时钟。
- OFDM 板级集成当前将 RX 通道 1 接入接收机；TX 通道 1 接 OFDM 样本，通道 2 固定为零。
- `board/TOP.xdc` 使用 `LVDS_25` 约束数据通路，AD936x SPI/控制脚采用 `LVCMOS25`。

## 4. OFDM 发射机

### 4.1 顶层控制与包缓存

`tx802p11_ip` 将可带间隙输入的 AXI-Stream 包缓存到片上 RAM，再对传统 PHY 核进行连续数据回放。命令中采样并校验包长、速率、上采样等元数据；当前支持包长 1..1024 字节，速率为 6、9、12、18、24、36、48、54 Mbps。接口没有 RF 样本反压机制，需连接到能接受每个 `m_valid` 样本的下游。[`rtl/ofdm/tx/tx802p11_ip.v`](rtl/ofdm/tx/tx802p11_ip.v)

### 4.2 发射处理链

依据 TX RTL 层次和 RS 文档，数据处理顺序为：

```text
用户 PSDU
 → CRC/FCS（CRC32）
 → 可选 RS(255,239) 外码与字节交织
 → 扰码
 → 卷积编码（母码率 1/2）
 → 按速率打孔
 → OFDM 比特交织
 → BPSK/QPSK/16-QAM/64-QAM 映射
 → 导频/数据子载波安排与 SIGNAL 生成
 → IFFT（由生成 IP 完成）
 → 循环前缀和时域帧输出
 → I/Q 缩放及 AD936x LVDS TX
```

TX 顶层源码注明调制映射：0=BPSK、1=QPSK、2=16-QAM、3=64-QAM；卷积码率控制值对应 1/2、2/3、3/4。具体速率到调制/码率的映射由 `tx802p11_ip` 控制逻辑完成。

### 4.3 TX 时序/吞吐约束

- PHY 接收完整用户包后缓存并连续回放；输入允许间隔，但发射核心不接收任意重叠事务。
- `tx802p11_ip` 有固定 32768 个 `data_clk` 周期的接收处理保护时间，80 MHz 下约 409.6 μs；`done` 表示 RF 样本发送完成，但内部 busy/接收命令限制可能继续保持。
- 该保护时间是在 RS 译码/串行接收延迟约束下采用的吞吐折衷，不是端到端延迟上界。
- 上电复位或错误恢复行为应与 DMA 控制器和 PHY 核联测。

## 5. OFDM 接收机

`rx802p11_top` 的主要处理职责包括前导检测与包控制，并将样本送入同步、频偏校正、FFT、导频/信道处理、解调和译码链路。由模块文件名、内部信号和测试说明可概括如下：

1. 短前导相关/能量检测，建立帧开始候选。
2. 长训练序列检测与符号边界对齐。
3. 粗频偏估计/校正，随后进行细频偏处理。
4. 去除循环前缀并送 FFT IP，进入频域子载波处理。
5. 利用训练序列估计信道；按 DATA/PILOT 子载波分离数据和导频。
6. 导频相位跟踪和信道平滑/均衡。
7. SIGNAL 字段解析获得速率与长度；按 BPSK/QPSK/QAM 做软/硬判决。
8. 比特去交织、Viterbi 解码和解扰。
9. 可选 RS 字节去交织/纠错，最后检查 CRC/FCS。
10. 仅在长度与 FCS 有效时产生可交付 payload 事件。

具体 FFT/Viterbi 的实现依赖工程中生成的 Xilinx IP；当前报告未在 Windows 环境重新生成或仿真这些 IP。仿真说明称部分 PHY 回归使用真实生成 IP，而不是行为级替代，但这只适用于对应记录的 XSim 构建条件。

### 5.1 单通道使用范围

PHY 层有双通道 I/Q 信号接口，但 `ad936x_ofdm_TOP` 当前只把通道 1 接入 OFDM RX/TX，TX 通道 2 固定为 0。因此不能因为 AD936x 或顶层支持多通道端口，就认定当前 OFDM 数据面实现了 MIMO、空间复用或 2T2R OFDM。

## 6. CRC 与 RS 外层纠错

### 6.1 RS 参数

- 码：缩短 RS(255,239)，GF(256)。
- 本原多项式：`0x11d`；生成多项式根：`alpha^0` 至 `alpha^15`。
- 每个码字含 16 个校验字节，可纠正至多 8 个符号/字节错误。
- CRC32/FCS 保留为最终包完整性检查；超过纠错半径时 RS 可能误纠到其他合法码字，因此 CRC 仍不可省略。
- 用户 payload 长度范围为 1..1024 字节；RS 输入包括 4 字节 CRC，最长 1028 字节。

### 6.2 当前源码的平衡字节交织

当前 RTL 默认 `RS_ENABLE=1`、`RS_INTERLEAVE=1`。令 `M=P+4`，`D=ceil(M/239)`，把 payload+CRC 平衡拆为 D 个连续数据块，分别 RS 编码后按列交织输出。没有额外校验开销；每个 lane 的长度最多相差 1 字节。接收端先去交织，再逐码字执行 RS 纠错。[`sim/RS_INTERLEAVE.md`](sim/RS_INTERLEAVE.md)

| 用户数据长度 P | RS 码字数 D | 可保证纠正的连续残余字节突发长度 |
|---:|---:|---:|
| 1..235 | 1 | 8 字节 |
| 236..474 | 2 | 16 字节 |
| 475..713 | 3 | 24 字节 |
| 714..952 | 4 | 32 字节 |
| 953..1024 | 5 | 40 字节 |

对 1024 字节用户数据，含 CRC 共 1028 字节，拆成 `206,206,206,205,205` 字节数据段，对应码字长度 `222,222,222,221,221`，总编码长度 1108 字节。每个 lane 仍只有 8 字节纠错能力。40 字节是有条件的**连续突发错误字节保证**：错误发生在 Viterbi 解码/解扰后的字节流，且各 lane 没有额外错误；它不是 RF 采样级干扰保证，也不是 BER/SNR 指标。

### 6.3 兼容性

RS/交织参数是编译期配置，没有空中自动协商。两端必须一致。`RS_INTERLEAVE=0` 可选择旧的非交织格式，`RS_ENABLE=0` 可旁路外码。普通 802.11 CRC-only 设备不理解该自定义 PSDU 编码方式。文档明确提醒，历史板卡镜像和 850 MHz 测量不能证明含有当前交织 RTL；重新编译 RTL 不会自动更新板卡。

## 7. 包接口、DMA 与控制寄存器

### 7.1 DMA TX 输入格式

`ofdm_dma_tx` 的 AXI-Stream 输入包以 `TLAST` 结尾，开头 16 字节为本地元数据，后续是 1..1024 字节无线 payload：

| 偏移 | 内容 |
|---:|---|
| 0..1 | payload 长度，小端 u16 |
| 2 | OFDM 速率值 |
| 3 | 上采样配置；当前适配器要求 0 |
| 4..7 | cookie，小端 u32 |
| 8..15 | 保留，要求为 0 |
| 16.. | 用户 payload |

TX 适配器目前允许的速率与 PHY 支持列表一致，使用若干 BRAM packet slot 缓冲输入；源码默认 `SLOT_BITS=2`，即 4 个 slot。队列满、长度/速率/保留字段错误会被拒绝。发送等待超时后会进入恢复状态并短时复位 PHY。[`rtl/board/ofdm_dma_tx.v`](rtl/board/ofdm_dma_tx.v)

固件通过 SG-DMA 描述符搬运数据；源码配置 128 个 TX/RX 描述符、2048 字节 slot、至多 4 个前置 outstanding 包，并在 CPU 与 DMA 间执行 D-cache flush/invalidate。TX cookie 与计数器用于关联状态。RX 数据必须满足 DMA SOF/EOF 描述符状态，长度 1..1024 字节，否则按 DMA 故障处理。[`firmware/dma_app/dma_transport.c`](firmware/dma_app/dma_transport.c)

### 7.2 DMA RX 提交策略

`ofdm_dma_rx` 在 FCS 到达前把解调字节暂存在包 RAM，不将未验证的部分包交给 DMA。提交要求：

- RX 包已开始且未超出 1024 字节缓存。
- FCS 有效。
- 观测字节数大于 0、至多 1024，并与 PHY 报告长度相同。
- RX 队列有可用 slot。

不满足条件会增加 drop/overflow/timeout 计数。AXI-Stream 输出在 `TREADY` 背压时保持稳定。[`rtl/board/ofdm_dma_rx.v`](rtl/board/ofdm_dma_rx.v)

### 7.3 AXI-Lite DMA 控制寄存器

`ofdm_dma_control` 的寄存器偏移如下（相对该 IP 的 AXI-Lite 基地址）：

| 偏移 | 读/写 | 说明 |
|---:|---|---|
| `0x00` | R | 版本/识别字 `0x444d4101`（ASCII 类似 DMA 标记） |
| `0x04` | R/W | bit 0 DMA enable；仅支持字节 strobe bit 0 写入 |
| `0x08` | R | 最大无线 payload 长度 1024 |
| `0x10` | R | TX submitted |
| `0x14` | R | TX completed |
| `0x18` | R | TX rejected |
| `0x1C` | R | TX failed |
| `0x20` | R | 最近 TX cookie |
| `0x24` | R | RX accepted |
| `0x28` | R | RX dropped |
| `0x2C` | R | RX overflow |
| `0x30` | R | RX timeout |

非法写地址返回 AXI SLVERR；读未定义地址返回 0。[`rtl/board/ofdm_dma_control.v`](rtl/board/ofdm_dma_control.v)

### 7.4 历史 mailbox 模式

当 `DMA_ENABLE=0` 时，`ad936x_ofdm_TOP` 实例化 `ofdm_packet_mailbox` 而不是 DMA 包适配器。mailbox 面向单个 64 字节请求，PS 通过 AXI-Lite 访问 TX/RX 数据窗口，用 toggle 握手在 AXI 与 PHY 时钟域之间传递快照，并对回收数据长度和内容做比较。其寄存器基址在历史文档中为 `0x43C10000`，与旧 `TR_mode` 控制地址区分。该接口和 DMA AXI-Stream 业务协议是不同版本/模式，不能混用。[`rtl/board/ofdm_packet_mailbox.v`](rtl/board/ofdm_packet_mailbox.v) [`host/PROTOCOL.md`](host/PROTOCOL.md)

## 8. PS 固件与主机协议

### 8.1 固件模块

- `firmware/radio/`：ADI AD9361 驱动、SPI/平台适配、射频初始化参数，以及原有应用入口。
- `firmware/dma_app/dma_transport.c`：AXI DMA SG ring 创建、RX buffer 预装、TX 提交、描述符回收和 cache 维护。
- `firmware/dma_app/link.c`：固定窗口发送、ACK、超时重试、重复包去重、失败计数及 UART 保留容量。
- `firmware/dma_app/services.c`：lwIP TCP listener、UART 帧解析、图像重组、CRC32 和状态记录。
- `firmware/dma_app/board_phy.c`：对已识别板载 PHY 的特定 BSP 行为适配；其他 PHY 保持 BSP 默认路径。

固件网络服务使用静态 IPv4 配置，默认构建参数由 `build_dma_sw.tcl` 提供；该脚本默认板卡 ID 为 10、子网编号为 1，TCP 监听端口 5001。文档中的现场配置曾使用 `192.168.137.10/24`，而主机协议示例使用 `192.168.1.10`。实际地址由构建参数/烧录固件决定，不能把示例地址当成所有固件的固定值。

### 8.2 无线数据包格式

主机业务包头长 24 字节，结构由 `host/dma_image.py` 的 `struct.Struct('<2sBBBBIIHHHI')` 定义：

| 字段 | 长度 | 含义 |
|---|---:|---|
| magic | 2 | ASCII `OF` |
| version | 1 | 当前为 1 |
| type | 1 | UART=1、图像元数据=2、图像数据=3、ACK=4 |
| flags | 1 | 当前要求 0 |
| channel | 1 | 业务通道 |
| session | 4 | 小端会话 ID |
| message | 4 | 小端消息/图像 ID |
| fragment index | 2 | 小端分片序号 |
| fragment count | 2 | 小端分片总数 |
| payload length | 2 | 小端 payload 字节数 |
| total length | 4 | 小端完整对象长度 |
| payload | 0..1000 | UART 数据或分片 |

无线包上限 1024 字节；UART payload 为 1..1000 字节。图像 TCP 传输以 1000 字节为一片，最大对象 16 MiB。服务端按会话/消息/通道关联分片，以 bitmap 防止重复写入，完成后用 CRC32 检查整个对象。

### 8.3 UART 业务封装

DMA UART 外层请求为 `A5 5A | packet_length(2 LE) | OF packet`；响应为 `5A A5 | record_length(2 LE) | record`。单字节 record 是本地 DMA 入队状态（0 接受、1 忙、2 无效）；较长记录是 RF RX 实际返回包。客户端必须同时收到入队成功和匹配 session/message 的回传数据，并比较 payload，才报告 PASS。

UART 波特率为 115200、8N1。主机工具依赖 `pyserial`；串口自动发现依赖工程现有 USB/FT2232 选择逻辑。

### 8.4 TCP 图像回环

TCP 客户端连接板卡 5001 端口，单板服务同时只接受一个 client。`dma_image.py loopback` 在同一连接中并发上传和读取回传记录，执行如下验收：

- 收齐回传分片并按序重组。
- 校验主机端 CRC32 和逐字节相等。
- 收到板端 CRC 结果和 ACK 窗口清空状态。
- 将数据先写入 `.part` 临时文件，再原子替换目标文件。
- 输出 SHA-256 摘要。

连接成功或 `sendall()` 成功并不代表无线回环成功。板端应用层 ACK/状态与 RX 返回内容均属于验收条件。

## 9. 仿真和验证

### 9.1 现有测试类型

`sim/` 中存在以下测试平台/runner：

- PHY 发射、RF 链路、IQ 缩放、频偏、导频、信道平滑和软判决测试。
- DMA 控制、DMA 包接口、背压、异常恢复和主机侧 DMA 服务测试。
- RS 编码/解码、包长度边界、错误注入、字节交织和旧格式兼容测试。
- 天线频率响应/增益模型的仿真特性测试。
- 主机 Python UART/TCP 协议、设备发现、数据分片和 benchmark 单元测试。

### 9.2 文档记录的 RS 交织回归结果

`sim/RS_INTERLEAVE.md` 记录了一次带源码 hash 校验的历史完成结果：

- 字节级 RS/交织回归 6,693/6,693 个包案例通过。
- 旧格式回归 204 案例、兼容性测试 22 案例通过。
- DMA 回归（含 27 项 DMA host tests）、全部 50 项 host tests、6 个 AD936x 接口场景通过。
- PHY 场景 14 项扩展为 21 个速率/场景组合；所有 8 种速率的 clean 1024-byte payload 被恢复。
- 记录的一个非交织参考退化场景 payload assertion 失败；文档将其作为 `reference_degradation` 明示，而非声称所有 raw case 均成功。
- RS 模块独立 OOC 路由：编码器+交织 LUT 504、FF 235、BRAM18 2，内部 WNS +4.551 ns；解交织+译码 LUT 1294、FF 969、BRAM18 1，内部 WNS +3.515 ns。它们不是整板资源/时序结果。

这些数字引用的是报告文件记录，未在本次分析中重新运行。其环境为 Vivado 2022.1、生成 IP 和指定 Linux 工程路径。当前 Windows 环境未检测到可用的 `rg`，也未执行 Vivado/XSim、Vitis/XSCT 或连接实体板卡。

### 9.3 历史整板构建与现场问题记录

`sim/RS_REGRESSION.md` 记录过启用 DMA/RS 的整板构建结果：WNS +0.400297 ns、WHS +0.006583 ns，逻辑资源约 70.30% LUT、48.02% FF、95.35% slice、65.71% BRAM、40.45% DSP。文档同时提示 hold 裕量偏小，外部 I/O 时序与 CDC 仍需板级复核；这不是当前源码重新构建结果。

`firmware/DMA_BRINGUP.md` 还记录过 DMA 描述符不完成和 PHY link 判断问题：AXI DMA 的可选 status/control stream 与设计不匹配时，S2MM 虽写入 DDR 但 RX descriptor 未完成；另有特定 PHY ID 的 lwIP BSP 识别适配。构建脚本会检查 XSA 参数，说明硬件 XSA 必须与固件匹配。这些是有价值的历史排障结论，不应假设现有 build 目录或板卡已经全部采用修复后的产物。

### 9.4 仿真和真实 RF 的区别

- RTL 错误注入（尤其在 Viterbi/解扰后注入字节错误）用于验证 RS 算法，不代表真实 RF burst channel。
- 仿真 FIR 天线模型是等效幅频响应模型，不模拟天线辐射方向图、阻抗、极化或电磁几何。
- CRC/逐字节比较证明某次回环 payload 正确，但不构成 BER/PER、灵敏度、发射频谱或长期可靠性统计。
- 既有测试文档明确列出未完成或未认证事项，包括板级 RF 统计、真实板级天线结果和某些当前 RTL 与旧镜像间的差异。

## 10. 构建、下载和运行概要

### 10.1 工具链

工程文档以 Linux 工作目录和 Xilinx 2022.1 工具为例，使用 Vivado 生成硬件实现和 XSA，再用 XSCT/Vitis 由匹配 XSA 创建 platform/BSP 并构建 ELF。主机 Python 测试还可能需要 `pyserial`。当前 Windows 工作区的本次分析没有检查本机 Xilinx 工具是否安装，也未实际执行构建。

### 10.2 推荐构建顺序

1. 确认需要 mailbox 还是 DMA 集成，设置板级 IP 的 `DMA_ENABLE`、RS 参数和 AXI DMA 参数。
2. 生成 Vivado 工程并执行综合、实现、bitstream 和硬件导出；检查时序、CDC、DRC、DMA 参数。
3. 将生成的 XSA 传给固件构建脚本；脚本应先校验 XSA，生成 BSP 并编译应用。
4. 使用同一组硬件/固件产物下载到板卡；初始化 PS/DDR 和 AD9361，确认 UART 的 `DMA ready` 信息及网络地址。
5. 先进行小包 UART 回环，再进行 TCP 图像回环；以 RX payload、CRC 和 ACK 完成为验收依据。
6. 保存 bitstream、XSA、ELF、生成参数、源码 hash、回归汇总和板卡射频配置，作为可追溯交付物。

文档中的 Linux 命令示例见 [`firmware/DMA_BRINGUP.md`](firmware/DMA_BRINGUP.md)。工程路径示例为 `/home/amd/ofdm/eeSDR_ofdm_loopback`，不能直接在 Windows 上照抄执行。

### 10.3 主机调用示例

```powershell
# UART：发送十六进制 payload，实际串口按设备情况指定或使用 auto
python host/dma_uart.py auto --hex 00112233445566778899aabbccddeeff

# TCP：单板图像回环。地址和路径需根据实际网络及文件调整
python host/dma_image.py loopback 192.168.1.10 C:\data\original.png --output C:\data\returned.png
```

该示例依据主机协议文档。执行前必须确认正在运行的板卡镜像是 DMA 版本、板卡 IP 正确、网络可达、RF TX→RX 路径已连接，并且当前固件与 RS wire format 一致。

## 11. 风险、限制与改进建议

### 11.1 配置/版本风险

1. **DMA 默认参数与部署模式差异：** 板级 RTL 参数默认 `DMA_ENABLE=0`，DMA 固件文档却描述 DMA 版。应将实际 Vivado IP 参数、XSA、bitstream 和 ELF 一并归档，并由启动端读取版本寄存器验证。
2. **RS 交织兼容性：** 当前源码默认交织，历史 bitstream/测量不一定包含该特性。建议在链路外提供明确版本配置或增加协议/控制面协商，至少在每次构建记录双方参数。
3. **目录产物时效：** `build_hw`、`build_sw` 和 `sim` 下可能同时存在不同时间产生的文件。不能仅凭文件存在或时间戳认定其与源码一致；应比对构建 manifest 和 SHA-256。
4. **网络地址差异：** 文档同时出现 `192.168.1.x` 和 `192.168.137.x` 示例。通过固件 build 参数和实际串口启动信息确认，不要硬编码误用。

### 11.2 时序和硬件验证

- 对 LVDS 外部接口补齐输入/输出延迟约束，复核数据/反馈时钟、源同步接口和 P/N 引脚约束。
- 对 PS/AXI/data_clk CDC 做完整报告审查；不能只依赖单个 WNS/WHS 数值。
- 对历史整板记录中较小的 hold 裕量进行复核；若修改任何 IP、时钟或约束，需重新跑整板实现。
- 进行 TX 功率、频谱、EVM、接收灵敏度、BER/PER、频偏范围和温漂测试；逐步改变衰减并使用合规的 RF 测试连接。
- 对 1T1R 作为当前有效 OFDM 模式进行验收；在实现和验证 MIMO 前，不宣称 2T2R OFDM。

### 11.3 软件可靠性与吞吐

- 记录 DMA descriptor 错误、DMA/PHY timeout、RF FCS fail、link retry、TCP retransmission 的独立计数，避免把 TCP 统计混为 RF 错误率。
- 在不同 payload 长度、帧速率和连续包负载下测试队列深度、TX guard、RX timeout 及 TCP 窗口的相互影响。
- 为硬件和固件增加统一版本/参数查询接口，包括 `RS_ENABLE`、`RS_INTERLEAVE`、DMA build ID、PHY rate、采样率和固件版本。
- 保留独立、可复现的回归清单；每次变更由源码 hash 关联结果，完整回归与子集回归明确区分。

### 11.4 文档治理

- 在根目录增加简洁 README，标明当前推荐构建配置和唯一有效部署流程。
- 为 `mailbox` 与 `DMA` 模式分别提供独立配置说明、主机工具和兼容性表。
- 对历史测试报告加上 source hash、bitstream/ELF hash、板卡编号和测试日期；把历史产物移出当前交付目录或标注为不可直接部署。

## 12. 结论

从当前源码可以确认，本工程具备完整的单通道 OFDM TX/RX 基带设计、AD936x LVDS 射频接口、CRC 与 RS 外码、RX 校验后提交、DMA 或 mailbox 数据接口、Zynq 网络/串口服务及主机回环工具。它不是只有 OFDM 调制器的单模块示例，而是覆盖 PHY、SoC 数据搬运、业务协议和测试工具的系统级工程。

同时，工程维护状态包含多个历史阶段：mailbox 和 SG-DMA 两种数据面、RS 非交织与当前交织 wire format、不同网络配置及多个生成产物并存。报告可确认的是“源码和资料中实现/记录了什么”，无法仅凭本地文件证明哪一套配置当前正在硬件上运行。工程交付或实物验收时，最关键的工作是锁定并验证同一组 RTL 参数、XSA、bitstream、ELF、主机协议和 RF 连接，并完成带版本 hash 的板级回归。
